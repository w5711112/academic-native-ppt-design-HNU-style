# 资产目录管理规范：独立子目录隔离与最小冗余原则 (Asset Directory Architecture)

本目录为演示文稿工程图表、矢量拓扑与实验响应图的根目录。为了彻底杜绝大模型在跨项目汇报中出现**“资产混淆复用”与“图文不匹配”**的严重事故，所有资产必须严格遵循以下三项物理架构铁律：

---

## 1. 独立子目录物理隔离 (Dedicated Subdirectory Isolation)

- **严禁根目录平铺**：`assets/` 根目录下**严禁**直接散落放置任何图像或矢量文件（除了本全局 `README.md` 之外）；
- **按项目素材独立建夹**：每一个演示文稿项目，必须根据其**素材标题或专题名称**，在 `assets/` 下建立独立的专用子目录：
  - 示例：`assets/投标文件--技术部分/`
  - 示例：`assets/博士学位论文答辩--视觉SLAM/`
  - 示例：`assets/国家自然科学基金申报--具身智能/`

---

## 2. 显式元数据与资产清单声明 (Asset Manifest & Metadata Binding)

每个项目专属子目录下必须包含一份 `README.md`，明确声明以下元数据：
1. **项目名称 (Project Title)**：当前 PPT 对应的项目完整名称；
2. **素材来源 (Source Document)**：提供图表与技术数据的原始输入文件；
3. **所属专题 (Topic)**：所属汇报主题或标段；
4. **生成/适用的 AI 模型 (Target Model)**：如 Gemini 2.5 Pro、Codex、Claude 3.7 或通用多模态模型；
5. **最小化资产映射表**：列出全部图片文件名、格式、对应 Slide 页码与工程图内容描述。

---

## 3. 最小必要原则 (Principle of Least Asset Redundancy)

- **无死图、无历史残留**：项目子目录内的图片总数必须**严格等于**生成的演示文稿实际引用的图片总数：
  $$N_{\text{assets}} = N_{\text{deck\_needed}}$$
- **即时清理与刷新**：每次根据新的素材或指派新的 AI 模型创建 PPT 时，必须重置或新建对应的专属子目录。严禁在旧项目目录中直接塞入新文件，更严禁在新项目中模糊检索旧目录的历史资产！
