# 学术 PPT 原生字体排版与数学公式规范 (Typography & Math Spec)

本文档定义了 `academic-native-ppt-design-HNU-style` 中的全域字阶梯队、原生双字体纯度法则、数学公式排版律与几何容器防溢出铁律。

## 一、字阶梯队与最小字号绝对红线

在 16:9 标准宽屏画布（`960 pt × 540 pt`）中，观众观看距离通常在 3 米至 15 米以上，严禁任何微小不可读的字体存在。必须严格执行阶梯化字阶规范：

| 角色 | 标准字阶 (pt) | 粗细与特征 | 典型颜色 | 适用范围与硬性规范 |
| :--- | :---: | :---: | :---: | :--- |
| **封面大标题** | `40 ~ 44 pt` | 加粗 (Bold) | `#FFFFFF` | 封面主标题，垂直居中，强制单行无折行。 |
| **封面汇报人/时间** | `24 pt` | 加粗 (Bold) | `#FFFFFF` | 封面汇报人与日期，垂直居中，单行无折行。 |
| **页面大标题** | `26 ~ 28 pt` | 加粗 (Bold) | `#A6232B` | 标准内容页左上角单行大标题，**最大不超过 28 pt**，强制单行无折行，与下方卡片左边界垂直平齐共线 (`X = 38.1 pt`)。 |
| **卡片区域副标题/要点小标题** | `20 ~ 22 pt` | 加粗 (Bold) | `#A6232B` / `#242424` | 各内容块、卡片顶部的提纲标题或序号标签。 |
| **正常正文文字与核心条目** | **`16 ~ 20 pt`** | 常规 / 重点加粗 | `#242424` | **卡片内部正常叙述文字**（密集排版用 16pt，常规排版用 17~18pt，精简排版用 19~20pt，根据当页排版容量自适应确定）。 |
| **密集技术注释与三线表格单元格** | `14 ~ 15 pt` | 常规 / 斜体 | `#242424` / `#666666` | **全域最小字号绝对底线**。三线表数据、图表坐标轴标注、公式变量注释、图注 (caption)。**绝对严禁低于 14.0 pt**！ |
| **页脚页码** | `14 pt` | 常规 | `#666666` | 右下角页码，弱化视觉干扰，双位数格式。 |

> [!CAUTION]
> **绝对禁令**：
> 1. 全域最小字号必须 $\ge 14.0\text{ pt}$，任何段落、文本框、表格单元格若低于 14.0 pt 均属严重违规；
> 2. 正常正文文字必须在 $16.0 \sim 20.0\text{ pt}$ 范围内，禁止将正文无节制压缩至 14pt；
> 3. 页面大标题必须 $\le 28.0\text{ pt}$，且必须单行容纳，不得两行折行。

## 二、双字体绝对纯度法则 (Native YaHei + Cambria Math)

学术与工业级汇报必须杜绝宋体、楷体与黑体混杂的业余排版感。

1. **中文正文字体**：
   - 统一强制为**微软雅黑（Microsoft YaHei）**；
   - 在 python-pptx 生成 DrawingML 时，**必须同时写入 `<a:ea typeface="Microsoft YaHei"/>` 与 `<a:latin typeface="Microsoft YaHei"/>`**，彻底杜绝 Windows PowerPoint 回退等线体或宋体；
   - 严禁宋体（SimSun）或等线（DengXian）作为正文字体。
2. **英文、数字与数学公式字体**：
   - 所有的数字、物理量、英文变量符号、数学表达式一律强制使用 **Cambria Math**；
   - 变量符号采用**数学斜体（Math Italic）**：如 $x, y, z, \theta, \omega, m, v$；
   - 算子、函数名与常数采用**数学正体（Roman）**：如 $\min, \max, \sin, \cos, \text{d}t, \exp$；
   - 希腊字母一律使用系统矢量字形，严禁使用低清位图公式贴片。
3. **原生 Office Math 公式体与颜色防隐形铁律 (<a14:m>)**：
   - **拒绝纯文本模拟**：复杂公式严禁以普通文本框模拟，必须采用 DrawingML 14 原生公式结构：
     ```xml
     <a14:m xmlns:a14="http://schemas.microsoft.com/office/drawing/2010/main"
            xmlns:m="http://schemas.openxmlformats.org/officeDocument/2006/math">
       <m:oMathPara>
         <m:oMath>
           ...
         </m:oMath>
       </m:oMathPara>
     </a14:m>
     ```
   - **颜色显式注入铁律**：公式内所有 `<m:rPr>` 下的 `<a:rPr>` 必须显式注入深灰字体颜色：
     ```xml
     <m:rPr>
       <a:rPr lang="en-US">
         <a:solidFill><a:srgbClr val="242424"/></a:solidFill>
       </a:rPr>
     </m:rPr>
     ```
     **关键机理**：若不显式指定颜色，PowerPoint 会继承幻灯片母版主题的默认白色字体，在白底卡片上将变成无法看清的“隐形文字”！
   - **正文物理变量角标下沉算法**：
     - 正文中出现如 $J_s, \lambda_c$ 等下标时，严禁输出裸露下划线 `_`；
     - 必须通过 DrawingML `<a:rPr baseline="-25000">` 实现物理角标下沉：
     ```xml
     <a:r><a:rPr sz="1500" baseline="-25000" i="1"><a:latin typeface="Cambria Math"/></a:rPr><a:t>s</a:t></a:r>
     ```

## 三、几何容器防溢出定律 (No-Text-Overflow Law)

在 PowerPoint 中，文本框超出边界或刺破卡片边框是严重的学术汇报事故。

1. **安全内边距（Padding）与表格 0 边距准则**：
   - **常规文本框与卡片容器**：显式配置 6~8 pt 安全内边距，防止文字溢出边缘：
     ```python
     tf.margin_left = Pt(8)
     tf.margin_right = Pt(8)
     tf.margin_top = Pt(6)
     tf.margin_bottom = Pt(6)
     tf.word_wrap = True
     ```
   - **表格单元格（0 边距与垂直居中铁律）**：
     - 表格内所有单元格上下左右边距**强制设为 0**：
       ```python
       cell.margin_left = Pt(0)
       cell.margin_right = Pt(0)
       cell.margin_top = Pt(0)
       cell.margin_bottom = Pt(0)
       cell.vertical_anchor = MSO_ANCHOR.MIDDLE
       ```
     - 彻底杜绝单元格文字因默认留白产生下坠、挤压折行或垂直不居中。
2. **文本容量预估与自适应微调**：
   - 单行容纳汉字数测算：$N \approx \frac{W_{\text{box}} - 16}{1.05 \times \text{FontSize}}$；
   - 例如：左侧方卡宽度为 $240\text{ pt}$，扣除 16pt 内边距后净宽 $224\text{ pt}$：
     - 在 17pt 字号下，每行约容纳 $12 \sim 13$ 个汉字；
     - 框高 $245\text{ pt}$，约可容纳 $7 \sim 8$ 行文字（行距 1.3 倍）。
   - **自适应微调机制**：
     - 若内容为 4~5 条要点：正文选用 16.0 pt，子标题 20.0 pt，段后距 3.0 pt；
     - 若内容为 2~3 条要点：正文选用 17.5 ~ 18.0 pt，子标题 21.0 pt，段后距 4.0 ~ 5.0 pt；
     - 若内容为 1~2 条精炼结论：正文选用 19.0 ~ 20.0 pt，子标题 22.0 pt，段后距 6.0 pt；
     - **狭窄文字框（宽 ~235pt）**：标题人工精细断句折行（如“空地异构设备\n联合自主导航与搜索”），正文采用 14pt 加大行距垂直撑满，配合宽幅图片展区，消除死角空白，确保页面饱满充实！

## 四、卡片垂直空间高充实度法则 (Vertical Fill Rate >= 80%)

针对“文字框下半部大面积死白、利用率不足 50%~60%”的学术汇报通病，制定量化充实度铁律：

1. **充实度量化指标定义**：
   $$\text{Fill Rate} = \frac{H_{\text{title}} + H_{\text{title\_gap}} + \sum (L_i \times \text{FontSize} \times 1.25) + \sum \text{SpaceAfter}}{H_{\text{card\_avail}}}$$
   - **红线底线**：$\text{Fill Rate} \ge 80.0\%$（低于 80% 判定为严重死白违规）；
   - **黄金区间**：$\text{Fill Rate} \in [85\%, 92\%]$（视觉饱满、呼吸感绝佳）；
   - **防溢出红线**：$\text{Fill Rate} \le 105.0\%$（严禁文字刺破卡片底边）。

2. **基准 1.25 倍行距与段距动态均分算法**：
   - 基准行间距统一设为 **`line_spacing = 1.25`**（空间格外充裕时可微调至 1.28）；
   - 标题与正文段后距基于目标高度（$0.88 \times H_{\text{avail}}$）动态反算均分：
     ```python
     free_for_spacing = (avail_h * 0.88) - (title_real_h + text_lines_h)
     if free_for_spacing > 0 and num_bullets > 0:
         space_after = max(5.0, min(14.0, free_for_spacing / (num_bullets + (0.5 if title else 0.0))))
         title_space_after = max(6.0, min(12.0, space_after * 1.1)) if title else 0.0
     ```

3. **内容量与行数预算矩阵 (Line Budget Matrix)**：
   - **左侧/顶部高卡 ($H = 247\text{ pt}$)**：总行数锁定在 **8 行**（4 个要点各 2 行，或 3 个要点 2+3+3 行），字符数精准控制在每条 $28 \sim 35$ 汉字（视卡宽而定），实测充实度稳定在 **$88\% \sim 91\%$**；
   - **底部横贯大卡 ($H = 140\text{ pt}, W = 622\text{ pt}$)**：总行数锁定在 **4 行**（2 个结构化要点各 2 行，每行约 40 汉字），实测充实度稳定在 **$90.7\%$**；
   - **底部中卡 ($H = 180\text{ pt}, W = 360\text{ pt}$)**：总行数锁定在 **6 行**（3 个结构化要点各 2 行，每行约 20 汉字），实测充实度稳定在 **$91.5\%$**。

通过“内容量充实 + 4分点结构化 + 1.25x行距 + 动态段距均分”的四维协同，彻底根治下部死白留白！

## 五、三层间距解耦、框间距大范围动态压缩与 14~15pt 高密度多要点容纳模型

针对“A-A框-B框-B”三层间距叠加（卡片内边距 8pt + 框间距 16~22pt + 图片内边距 8pt，实际视觉断裂跨度达 32~38pt）导致的版面碎裂与空间浪费，建立间距解耦与双模态排版机制。

### 1. 两种间距优化解耦模态对比与参数规范

| 间距模态 | 适用场景 | 文本框边距 (`margin`) | 图片容器内距 (`padding`) | 相邻框间距 (`gap`) | 视觉质感与核心收益 |
| :--- | :--- | :---: | :---: | :---: | :--- |
| **模态 1：零内边距贴边扩展模态 (Zero-Padding Mode)** | **图大字多、技术机理密集页首选** | `0 pt`（文字从容器最左侧起排） | `0 pt`（图片顶满容器边界） | **`6.0 ~ 12.0 pt`**（主推 8~10pt） | 保持卡片现代悬浮感的同时，彻底释放容器内部 100% 空间，图片可大幅展宽 15%~25%，文字行宽增加 1~2 个汉字。 |
| **模态 2：无缝衔接/宏观一体化模态 (Seamless Docking Mode)** | **流程链、时序阶段、多机对比面板** | `8.0 ~ 10.0 pt`（内部舒适呼吸） | `0 ~ 4.0 pt` | **`0 ~ 4.0 pt`**（紧密咬合或大底卡统一包裹） | 消除卡片间的琐碎缝隙，形成工业控制台/集成仪表板的一体化高级版面，杜绝碎块感。 |

### 2. 双模态字阶动态分流与多要点容量模型 (Capacity Formulation)

> [!IMPORTANT]
> **小字号专为容纳更多内容服务**：严禁在内容精炼时盲目下压字号。只有当技术内容多、分点多或用户明确要求高密度详述时，才启用 14~15pt 主阶。

#### 2.1 高密度技术详述模式 (`14.0 ~ 15.0 pt`, 主推 14.5pt / 15.0pt)
- **触发条件**：分点数量达到 **4 ~ 7 个结构化要点**，或单卡文字量超过 150 汉字；
- **排版参数**：正文字号取 `14.5 pt` 或 `15.0 pt`，行距设为 `1.25x`，段距收紧至 `3.0 ~ 5.0 pt`；
- **同页极差收敛**：同页内所有卡片正文字号极差必须 $\le 1.0\text{ pt}$（通常全页统一锁定 14.5pt 或 15.0pt）；
- **容量预算公式**：
  $$N_{\text{max\_points}} \approx \left\lfloor \frac{H_{\text{avail}} - H_{\text{title}} - 8}{2 \times (14.5 \times 1.25) + 4} \right\rfloor$$
  在典型左高卡（$H = 247\text{ pt}$）中，可从容容纳 **5 ~ 6 个两行分点** 或 **4 个三行深度论证分点**，利用率稳定在 **$88\% \sim 93\%$**。

#### 2.2 标准/精炼汇报模式 (`16.0 ~ 18.0 pt`)
- **触发条件**：常规技术汇报、总结提炼、分点数量在 **2 ~ 3 个要点**；
- **排版参数**：正文字号取 `16.5 ~ 18.0 pt`，行距设为 `1.25x`，段距均分为 `6.0 ~ 10.0 pt`；
- **同页极差收敛**：极差 $\le 1.5\text{ pt}$，确保 3 米至 10 米外极佳远视距清晰度；
- **坚决杜绝**：内容仅有 2 点时盲目使用 14pt 导致卡片底部死白，或内容有 6 点时硬套 18pt 导致文字刺破卡片底边。
